# Настройка и проверка маршрута

Маршрут Claude Code проверен по публичной документации 27.09.2026 и локальному
CLI 2.1.283. Основные источники — документация headless/CLI и модели Opus 5.5;
ссылки и границы адаптации см. в `sources.md`, команды — в `runner.md`.

## Три независимых слоя

1. Skill: кто планирует, кому поручать работу, как принимать результат.
2. Локальный runner: запуск `claude -p`, модель, brief, отчёт и session ID.
3. Claude Code: собственные инструменты, настройки провайдера и авторизация.

Используй установленный `claude` через `scripts/run_phase.py`.
Runner выбирает `claude-opus-5-5`, передаёт полный brief через stdin, сохраняет
вывод и метаданные. Инструменты Agent/Task запрещены; инструкции также запрещают
вложенное делегирование через CLI, skills и MCP. Не рассчитывай на это как на
отдельную файловую sandbox: ограничения writable paths также должны соблюдаться.

**Обязательная предпосылка:** Claude Code уже установлен и имеет разрешённую
рабочую авторизацию. Основная Astra-сессия сохраняет свой существующий маршрут;
ей не требуется общий с исполнителем LiteLLM provider. Этот пакет не исправляет
авторизацию и не устанавливает relay, сервер или дополнительный CLI.

Точный model ID — `claude-opus-5-5` (Opus 5.5). Не заменяй его плавающим alias
`opus` и не добавляй fallback. При явном запросе пользователя на другую модель
передай `--model`; без такого запроса сохрани default runner. Для Opus 5.5 обязательно
передавай `--effort medium` при каждом запуске, включая resume и повтор после сбоя,
если пользователь не задал иное. Effort основной Astra-сессии и настройки Claude Code
не определяют это значение. Пользовательский override передавай явно и сохраняй
при продолжении той же задачи; значение должно поддерживаться CLI/моделью.

Сохраняй существующие URL, заголовки, credentials и provider settings обоих
клиентов. Не печатай переменные авторизации. Никакие ключи или конкретный
адрес сервера не встроены в пакет. При уже настроенном внешнем proxy нельзя
объявлять upstream прямым только потому, что runner локальный: сверяй метаданные.

## Ранее настроенный Claude Code

Используй существующую конфигурацию Claude Code, сохраняя её дополнительные
инструкции. Этот skill не устанавливает и не заменяет Codex role или CLI settings.

Claude Code загружает собственные project guidance, hooks и MCP. Инструменты
и разрешения основной Codex-сессии автоматически не переносятся. Проверь
необходимые для фазы инструменты, особенно браузер и visual QA. Не используй
`--bare` как случайный способ изоляции: он меняет загрузку настроек и авторизацию.

Не меняй `[agents].default_subagent_model`: этот runner не использует нативный
spawn и не должен перенастраивать других субагентов. Если проектные настройки
Claude конфликтуют с требуемым маршрутом, явно диагностируй конфликт, а не
обходи его другой моделью или изменением глобальных настроек.

Авторизация интерактивного Claude Code может быть недоступна процессу внутри
sandbox host: например, из-за ограничений доступа к системному хранилищу
credentials, сети или записи сессий. `Not logged in` само по себе не доказывает
ни отсутствие авторизации у пользователя, ни конкретную причину сбоя.
Не запускай `/login`, не извлекай ключи и не меняй provider settings автоматически.
При установленной или обоснованно предполагаемой связи с sandbox используй
штатный механизм host для разрешения запуска runner вне него; инструкция skill
не заменяет это разрешение. Порядок запуска и восстановления без лишнего resume
описан в `runner.md`, раздел «Sandbox host и ранняя ошибка авторизации».

## Статическая проверка перед первой работой

Проверь фактическую основную модель, выбранный profile, CLI/UI overrides и
проектные настройки. Проверь `claude --version` и нужные строки `claude --help` (отфильтруй вывод,
не загружай всю справку): требуются
`-p`, JSON output/schema, `--session-id`, `--resume`, `--effort`, `--permission-prompts none`.
Последний флаг требует v2.1.259+. Python runner требует Python 3.9+ и macOS/Linux.

Убедись, что shell host может запустить процесс в нужном workspace. Runner
использует `dontAsk`, разрешает обычные файловые инструменты и принимает
дополнительные разрешённые правила через `--allow-tool`. Не добавляй permission
bypass; при отказе назови конкретный блокер. Файловый lock координирует только
запуски этого runner, а не произвольные CLI или редакторы.

Наличие установленного CLI не подтверждает все уровни конфигурации и не
объявляет runtime рабочим. Ответ списка моделей также не доказывает
многошаговую работу инструментов или фактический upstream.

## Проверка реального вызова

Первая разрешённая задача должна быть небольшой и полезной: например,
изменение функции и теста в тестовом проекте без приватных данных.
Проверь метаданные session/request, доступные в Claude Code и у провайдера:

| Что | Ожидаемое наблюдение |
|---|---|
| Основной thread | выбранная пользователем Astra |
| CLI-сессия | ID из runner metadata совпадает с session ID результата |
| Модель | `claude-opus-5-5` в метаданных использования модели |
| Upstream | разрешённый провайдер / модель, без неожиданного fallback |
| Инструменты | чтение, изменение, проверка и продолжение после tool output |
| Коррекция | `--resume-from` продолжает тот же session ID, новый run directory |

Запрошенный model ID сам по себе не доказывает upstream. Сверяй доступные
CLI/provider metadata, а не слова исполнителя. Не копируй секретные заголовки,
полные request bodies или приватные журналы в отчёт. Реальную работу инструментов
оценивай по изменениям файлов и проверяемым результатам.

`static_only`: проверены CLI/model ID, но не фактический запрос.
`inference_verified`: запрос связанной CLI-сессии и upstream проверен по метаданным;
результаты инструментов всё равно оцениваются отдельно.
`unverified`: метаданные недоступны, неоднозначны либо не совпали.
Не выдавай static_only за inference_verified. Если route не подтверждён,
не делегируй чувствительный код без разрешённой политики передачи данных.
После смены model/provider/fallback/client проверку соответствия повтори.

## Типовые блокеры

- CLI нет: проверь фактический PATH и разрешённую установку. Не устанавливай
  другой CLI, не переходи на native Codex child или relay как обход.
- Unknown model: сравни точный ID, CLI overrides и настройки провайдера.
  Не подменяй модель на плавающий alias и не включай fallback.
- Неподдерживаемый effort: выясни допустимые значения текущего маршрута;
  не наследуй xhigh/ultra от Astra и не отключай reasoning молча.
- 401/403: проверь существующую схему авторизации без вывода секретов;
  не меняй заголовки или разрешения автоматически.
- `Not logged in` до первого API-вызова: проверь безопасные поля результата
  и условия запуска по `runner.md`; не считай созданный runner session ID
  доказательством сохранённой Claude-сессии.
- Tool/JSON error: сохрани stdout, stderr и metadata; это не повод написать код
  основной моделью и назвать результат работой Claude Code.
- Permission denial: передай точную команду Astra через `needs_permission` и
  `permission-request.json`; решение и resume описаны в `permissions.md`.
  Не расширяй разрешения автоматически и не обходи host/managed policy.
- Resume не найден: ранний сбой мог не сохранить сессию в Claude. Не запускай
  новую сессию молча и не используй `--continue` для выбора случайного диалога.
- CLI отвечает, но агент не пишет: проверь многошаговый цикл инструментов,
  а не только текстовый запрос «OK».

Skill не гарантирует выбор upstream при настроенных серверных fallbacks,
не является scheduler или границей безопасности и не измеряет расходы сам.
CLI cost fields — оценки; при resume они могут включать прошлые обращения.
